# 2026-11-10：<用atomic+dp跑crossword任务>

## 做了什么

今天跑了用了recovery数据训练的dp模型做crossword任务，做MARS，用gemini和astra都跑了。

## 观察到了什么

recovery数据可能会把模型训练坏，采集recovery的时候不能主动示范错误动作，要从错误动作结束阶段做起，示范正确的动作。不然在deploy的时候机器人会主动做错误的动作。



vlm当作checker会有和policy执行和molmopoint打点的频率互斥问题。比如每当机械臂做一个place动作的时候，动作做到一半，还没做完，vlm checker就打断进行check,导致机械臂未回到home状态，遮挡了目标方块，vlm check三次后没有找到point便自动退出程序。



dp对相机图像的要求很高，我们的外部相机放置有点歪，往右侧倾斜，所以当目标物体在右侧的时候，point的像素点位置准确特别重要，如果偏移了一点对于policy来说，成功率就会下降很多。并且我们目前的方法对于腕部相机的使用不高，这可能是训练的问题，我们把腕部相机的point embedding向量长度增长到512了（之前是128）dp的效果还是不好，腕部相机对于policy影响依然远不如external camera.并且dp训练后有很强的动作惯性，或者是overfitting,稍微动一下方格摆放位置效果可能差别很大；泛化性不好，训练是用的四个字母，deploy加一个字母就放不了了，第五个字母还是会当作第四个字母放。



gemini总是断触真是服了，astra好很多，并且astra会replan,会调整phase,gemini基本不会replan.

## 理解

claude的理解：

### 1. Recovery 数据：结论对

示范了"犯错"的那段，模型就会把犯错当成正常动作学进去。两种做法都可以：

- **只录纠正段**：从错误状态开始录，只示范正确动作，就是你说的做法。
- **录全程但不训练错误段**：把错误段标成单独的 phase 或直接从训练里去掉。

需要留意的是，recovery 的起始状态要覆盖 deploy 时真实出现的失败状态，而不是你想象的失败状态。最好直接从昨天的失败 rollout 里取状态来摆。

### 2. Checker 打断：不是频率互斥，是 replan 后在遮挡画面上重新打点

按 `runner.py` 的逻辑，check 只在 action chunk 边界发生，每个 phase 内每 64 步一次，本身只是让机械臂停住，不会导致退出。真正导致退出的链条是：

1. checker 在 place 做到一半时报了 `needs_replan`。配置里 `min_steps_before_replan: 0`，所以立刻 replan。
2. replan 进入新计划时把 `cached_point` 清空，并强制重新打点。
3. 这时机械臂还停在目标上方，外部相机被挡住，MolmoPoint 找不到点。
4. 没有旧点可用，episode 以 `grounding_failed` 结束。

所以调 check 频率治标不治本。更直接的改法，按改动量从小到大：

- **保留旧点**：同一个物体/目标的点在 replan 和 phase 切换后继续作为 fallback，不清空。preplace 和 place 的目标是同一个，place 开始时夹爪本来就在目标正上方，这个位置打点天然容易被挡。
- **延迟 replan**：把 `min_steps_before_replan` 设成大于 0，或要求连续两次 check 都说失败才 replan。
- **先让开再打点**：重新打点前先抬升或回到一个不遮挡的观察位姿。
- **按事件触发 check**：用夹爪开合变化、末端速度接近零来触发，而不是固定步数。

### 3. DP 的问题：我认为核心是 policy 没在用 point，不是相机歪

你列的几个现象指向同一个原因：

- **第五个字母被当成第四个放**：这是最强的证据。训练只有四个字母，每个 phase 一个静态点，point 实际上只有几个取值，模型可以把它当类别标签，甚至完全忽略，只靠图像和关节状态背轨迹。
- **把 embedding 从 128 加到 512 没用**：符合上面的解释，瓶颈不在容量。代码里 point 只是一个 2 维坐标过 MLP 后拼到 global condition 上，和图像特征没有空间对应；视觉又用的是 CLIP ViT-B/32 的 CLS token，空间精度本来就粗。
- **动作惯性、挪一点位置就失败**：action 是绝对关节角，输入里也有关节状态，这个组合很容易记住轨迹。
- **腕部相机没用**：外部相机加关节状态已经足够解释训练集里的动作，模型没有动力去看腕部。
- **右侧对点更敏感**：相机歪本身不是问题，只要训练和 deploy 一致。更可能是右侧离相机更远或更斜，同样一个像素对应的桌面距离更大。另外 `custom/dataset.py` 里 point 没有任何噪声增强，训练时见到的都是干净的标注点。
